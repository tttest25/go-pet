# T25 — Версионный обработчик и публичный результат runner

Runner выберет один из трёх установленных обработчиков v1 и перед `completed` опубликует отдельный `out/<job_id>/public.json`. Старые задания без версии продолжат выполняться; неизвестная версия, недоступный обработчик или невалидный вывод приведут к `failed` без публикации.

**Приоритет и границы.** Первый открытый пункт в `todo.md`, раздел «Каталог действий и универсальное выполнение»; источник — `.opencode/tasks/go_pet_actions_roadmap.md`, T25. Карта описывает последовательность, фактическое закрытие T22–T24 отмечено в todo. Передача версии из T24 уже работает. Один шаг: Bash runner, его Go harness и описание файлового контракта в README/architecture. Без изменений схемы, Go API, writer, обратного заполнения истории, endpoint/лимита ответа T26 или действия T27.

## Исходное состояние (проверено чтением, без запуска тестов)

- `internal/db/queue.go` читает версию выбранной строки задания, `internal/spool/writer.go` сериализует её числом в верхнеуровневый `action_version`. `internal/db/create_action_test.go` проверяет в том числе v1 для legacy. Runner не должен выводить версию из payload или заново запрашивать каталог.
- В `scripts/spool-runner.sh` `validated_tool` проверяет `tool_name`, совпадение с `payload.tool` и аргументы; `process_job` ветвится только по имени. `run_tool` уже ограничивает время и разделяет stderr. После exit 0 `yt-dlp` может отправить `completed` даже при битом stdout. Для fabric внутренний `result.json` содержит host `output_path`. Публичной проекции нет.
- `scripts/spool_runner_test.go`: `newRunnerFixture` создаёт временный spool, изолированный PATH и fake curl/CLI; `job` пишет **без** версии. `TestRunnerToolExecution`, `TestRunnerMissingCLI`, `TestRunnerToolTimeout`, `TestRunnerCallback`, `TestRunnerInvalidJob`, `TestRunnerSpoolLock` закрепляют legacy-артефакты, argv/stdin, ошибки и восстановление. В успешных fixtures yt-dlp используются `{"captured":true}` и `{"ok":true}`; для нового критерия успеха нужны образцы с title/description.

## Согласованный контракт и приёмка

1. Диспетчеризация — закрытый перечень `(echo-test,1)`, `(fabric,1)`, `(yt-dlp,1)`. Только отсутствие `action_version` означает v1; явные `null`, строка, boolean, дробная или неподдерживаемая версия — отказ. Не запускать имя, путь или команду из JSON. Сохранить существующие проверки payload и передачу фиксированных argv/stdin.
2. Для каждого успешного запуска — один JSON-объект с ровно `type` (имя действия), `version` (число 1, версия формата результата), `data` (объект). Схему задаёт выбранный обработчик, а не присланные поля. Приёмка сравнением декодированного документа целиком:
   - echo: `{"type":"echo-test","version":1,"data":{"echo":"hello"}}`; без message — `"default echo"`. Не обрезать переводы строк.
   - fabric: `data: {"text":"…"}` — полное непустое UTF-8 содержимое stdout из `output.md`, включая завершающие переводы строк. Проверять байты до преобразования в JSON; тихая замена невалидного UTF-8 недопустима.
   - yt-dlp: `data: {"items":[…]}` — непустой список в порядке объектов stdout, поддержать как один объект, так и поток объектов `--dump-json`. В каждый элемент проецировать только строковые `title` и/или `description`; нужна хотя бы одна из этих строк в **каждом** объекте. Пустой поток, битый хвост, не-объект, отсутствие обеих строк → отказ всей публикации.
3. Не переносить `result_path`, `output_path`, полный stdout метаданных, служебные поля и stderr в оболочку. При этом текст самого результата не редактировать. Сохранить внутренние `result.json`, `output.md`, `stderr.log` и значение callback `/spool/out/<job_id>/result.json`; не менять подтверждение только по 204. Старые завершённые задания не обрабатывать.
4. Публиковать полностью подготовленный файл переименованием из временного файла в том же каталоге **до** отправки `completed`. Не считать `public.json` от прежней попытки результатом новой при ручном повторе того же ID. При подтверждённом `in_progress` и отказе — один `failed`, без `completed` и нового/устаревшего публичного файла; доступные внутренние диагностические артефакты остаются. При потере подтверждения терминального callback сохранить `processing` и доступные результаты для сверки; не повторять callback.
